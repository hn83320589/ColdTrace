# ColdTrace 教學：從題目到可交付系統

> 以一個真實規模的題目「疫苗冷藏櫃溫度監測平台」為教材，完整走過
> **需求分析 → 系統分析 → 架構設計 → 技術選型 → 實作 → 核心演算法 → 測試 → 檢討**。
> 所有程式碼片段都取自本 repo，可以邊讀邊打開原始檔對照。

## 這份教材想教什麼

多數教學範例「收資料、存資料庫、畫圖表」就結束了。這個題目真正的難點在於
**資料不可靠**：會重送、會亂序、會晚到 72 小時、裝置會被更換、伺服器自己也會停機。
讀完這份教材，你應該能夠：

1. 從一份文字題目中找出**隱含需求**與**模糊點**，並把驗收標準改寫成可執行的測試。
2. 用**領域模型、狀態機、時間模型**描述系統，在寫程式前就發現邊界情境。
3. 理解「**判定結果 = f(資料)**，資料庫只負責對帳」這個讓系統對重送與補傳免疫的核心設計。
4. 為每個技術選擇寫出**理由與替代方案**，而不是「大家都用」。
5. 讀懂並能自己實作三個核心演算法：超標連續段偵測、事件對帳（延長／合併）、資料覆蓋率判定。
6. 用**可注入時鐘**讓「等 15 分鐘」「斷線 2 小時」這類時間邏輯可以在毫秒內測完。
7. 從外部 code review 找到的缺陷中學到：**假設事項需要防禦，而不只是寫在文件裡**。

## 建議閱讀路線

- **系統分析／架構課程**：01 → 02 → 03 → 04 → 10
- **程式設計／演算法課程**：02（時間模型）→ 05 → 06 → 07 → 08 → 09
- **只有一小時**：01 的「隱含需求」、03 的「核心設計原則」、06 全章

## 先備知識

- TypeScript 基礎（型別、介面、class）
- SQL 基礎（SELECT、INSERT、索引、transaction）
- 知道 HTTP API 與 WebSocket 的差別
- React 基礎（hook、元件）——只有第 08 章需要

## 動手跑起來

```bash
npm install
npm run dev          # 後端 + 前端 + 正常情境模擬器，開 http://localhost:5173
npm test             # 97 個測試
```

加速展示（1 秒 = 1 分鐘），可在幾分鐘內看到「斷線 2 小時後補傳」的完整過程：

```bash
CLOCK_SPEED=60 npm run dev:no-sim
npm run simulator -- --scenario normal --override TM-0007=offline-backfill
```
